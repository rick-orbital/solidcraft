# Managed editor contract v1

The versioned JSON schemas define the initial window handshake and subsequent control envelopes. The frame fetches `/runtime-config.json` from its own origin and fails closed unless `allowedParentOrigins` contains valid exact HTTPS origins or loopback HTTP origins. Once config is loaded and the listener is installed, it sends `{ "type": "curie.cad.listening", "version": { "major": 1, "minor": 0 } }` only to a configured exact parent origin. This bootstrap conveys no authority. The parent validates its origin and `source` before sending the schema-defined init with one transferred port; the editor validates parent source and configured origin and sends ready on the port. Reject duplicates, incompatible major versions and stale bindings. Do not use wildcard target origins. The parent retains credentials and server authorization; the port is not a write grant.

Control messages are bounded and binary transfers are separately size checked. The initial envelope deliberately reserves operation-specific validation to later schema fixtures; no operation may be enabled on the basis of the generic envelope alone. Generation and fencing counters are decimal strings. A new document or reload establishes a new epoch. A snapshot captures bytes, document identity and generation under exclusion; only the persistence service may acknowledge a saved revision. An ambiguous dispatched mutation is not replayed automatically and blocks further mutations pending reconciliation or explicit recovery.

The initial read-only payloads are `{ "action": "capabilities" }`, `{ "action": "load", "bytes": ArrayBuffer }`, and `{ "action": "snapshot" }`. `load` transfers exactly one ArrayBuffer, at most 16 MiB, and is accepted only once per epoch before editing. `snapshot` transfers one bounded ArrayBuffer. The parent enforces the limit before sending; the receiver validates message shape, buffer type and byteLength before copying or parsing. Responses use `{ "ok": true, "result": ... }` or `{ "ok": false, "error": { "code": ... } }`. Capabilities report `actions`, `maxDocumentBytes`, `writable: false`, protocol and build identity; load and snapshot report `documentId` and decimal `generation`. Only one operation may be in flight. External DesignLinks are rejected explicitly. No operation enables native editing or authorizes a save.

The first agent path adds scoped `document.inspect` and `parameter.change` actions. `document.inspect` returns bounded named parameters, units, measurements, `documentId` and decimal generation. `parameter.change` accepts exactly one `{name, expression}` and requires operation ID plus expected generation, the already-bound design/epoch, active editing lease and quiescent exclusive execution. A successful response reports applied result, inspected parameter values and resulting generation; it does not report Saved. Errors include `stale_generation`, `editor_busy`, `invalid_parameter` and `lease_lost`. The parent verifies and snapshots, then requests a service commit bound to operation ID and accepted revision. An ambiguous dispatched result freezes further mutations pending reconciliation or explicit recovery; it is never automatically replayed.

For the reference bracket, inspection may include bounded `body_faces` geometry from the engine registry, including cylinder axis origin/direction and radius. Consumers deduplicate split faces before comparing hole axes and must not infer hole locations from face counts. Missing required geometry refuses mutation before dispatch; same-engine measurements are not an independent export oracle.

For the first parameter operation, the parent captures a stable pre-mutation native snapshot. A definite post-apply verification failure before committing may invoke bounded `snapshot.restore` with the same operation ID and applied generation, bound to the same design and epoch under a valid lease and exclusive quiescent lock. Restoration retains the managed document identity, advances generation, and is reported as rollback verified only after byte-identical snapshot and relevant inspection checks. The service accepts the claim-bound `rollback_verified` terminal failure assertion only before commit. A failed or uncertain restoration freezes editing. A lost or ambiguous commit is not automatically rolled back or replayed.

`export.step` and `export.stl` require the expected generation and execute on a quiescent locked editor; they return bounded transferable bytes with document ID, generation, format, units and settings. The parent may publish only a verified clean snapshot associated with an authorized accepted revision and must recheck identity, head and generation. Output size validation occurs after engine generation and does not bound transient engine memory. Publication records revision, build, format, settings, size and hash; source association is an authenticated editor assertion, not cryptographic proof of geometry. STL is unitless and the intended scale is recorded.

`import.step` is a user-initiated operation with a single transferred ArrayBuffer capped at 16 MiB, operation ID and expected generation. The initial path is admitted only after `load.empty` on a newly authorized, no-head design with a valid edit lease and exclusive quiescent lock. It uses a checkpoint, removes its unique temporary VFS data on every outcome, and commits through the normal fenced revision path; it does not silently replace an existing design or imply reconstruction of feature history. STEP parsing is synchronous in the pinned engine: show busy state, treat deadline ambiguity as unknown and freeze, and record fixture latency and supported limits.
